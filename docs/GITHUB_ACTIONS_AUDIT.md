# GitHub Actions Audit

**Audit Date:** 2026-08-26  

---

## Current State

**No GitHub Actions workflows exist.** The `.github/workflows/` directory does not exist in the project.

All builds are currently done locally using:
- `flutter build appbundle --release` (manual)
- Local keystore at `android/keys/release.keystore`
- Local `key.properties` with plaintext passwords
- Local Flutter SDK at `E:\flutter`
- Local Android SDK at `E:\Android\sdk`

This is **not reproducible** on a clean CI runner.

## Requirements for GitHub Actions

### Runner
- **Recommended:** `ubuntu-latest` (Linux)
- **Justification:** Flutter Android builds work on Linux. No Windows-specific compilation needed. Linux runners are faster and cheaper.
- **Note:** iOS builds would require macOS runner, but this audit focuses on Android/Play Store.

### Java Version
- **Required:** JDK 17
- **Reason:** `compileOptions` in `app/build.gradle` specifies Java 17
- **Action:** Use `actions/setup-java@v4` with `java-version: '17'` and `distribution: 'temurin'`

### Flutter Version
- **Required:** Flutter >= 3.6.1 (per `pubspec.yaml` SDK constraint)
- **Recommended:** Latest stable channel
- **Action:** Use `subosito/flutter-action@v2` with `flutter-version: 'stable'`

### Gradle
- **Required:** Gradle 8.12 (per `gradle-wrapper.properties`)
- **Action:** Use Gradle wrapper (`./gradlew`) — do NOT install Gradle globally
- **Caching:** Cache Gradle dependencies and wrapper distributions

### Signing
- **Method:** GitHub repository secrets
- **Required secrets:**
  - `ANDROID_KEYSTORE_BASE64` — Base64-encoded upload keystore
  - `ANDROID_KEYSTORE_PASSWORD` — Keystore store password
  - `ANDROID_KEY_PASSWORD` — Key password
  - `ANDROID_KEY_ALIAS` — Key alias
- **Process:** Decode keystore from base64 → write to temporary file → build signed release → cleanup

## Proposed Workflows

### 1. `android-build.yml` — CI Build & Test

**Triggers:** Push to main/develop, Pull Requests  
**Purpose:** Validate code compiles, run lint, run tests, build debug APK

**Steps:**
1. Checkout repository
2. Setup Java 17
3. Setup Flutter (stable)
4. Cache Gradle and Flutter dependencies
5. `flutter pub get`
6. `flutter analyze` (Dart static analysis)
7. `flutter test` (unit tests)
8. `flutter build apk --debug` (debug build)
9. Upload debug APK artifact

### 2. `android-release.yml` — Signed Release AAB

**Triggers:** `workflow_dispatch`, tags matching `v*`  
**Purpose:** Build signed release AAB for Google Play

**Steps:**
1. Checkout repository
2. Setup Java 17
3. Setup Flutter (stable)
4. Cache Gradle and Flutter dependencies
5. Decode keystore from GitHub Secret
6. Create `key.properties` from GitHub Secrets
7. `flutter build appbundle --release` (signed release AAB)
8. Upload AAB artifact
9. Upload mapping file (for crash symbolication)
10. Cleanup keystore and key.properties

## Caching Strategy

| Cache Key | What | Why |
|-----------|------|-----|
| `gradle-wrapper` | Gradle wrapper distribution | Avoid re-downloading Gradle 8.12 |
| `gradle-deps` | Gradle dependencies (~/.gradle/caches) | Speed up builds |
| `flutter-pub` | Flutter packages (~/.pub-cache) | Speed up `flutter pub get` |

## Security Considerations

1. **Never echo secrets** — GitHub Actions masks secret values in logs automatically, but avoid printing them
2. **Keystore cleanup** — Delete temporary keystore file after build (runner is ephemeral, but good practice)
3. **No secrets in artifacts** — Ensure `key.properties` and keystore are not included in uploaded artifacts
4. **Environment protection** — Use GitHub Environment `production` for release builds with required reviewers
